# Akkhara `v3.1.3-alpha.3` — ထွက်ရှိမှု မှတ်တမ်း

**ထွက်ရှိသည့် ရက်စွဲ:** ၂၀၂၆ နိုဝင်ဘာ ၂၅
**အထူးအဆင့် (tag):** `v3.1.3-alpha.3`

ဤဗားရှင်းသည် native `akk build` backend ၏ slice ကို နောက်တစ်ဆင့်
တိုးချဲ့ပါသည် — `sqrt(x)` (စတုရန်းမြစ်) ကို executable ထဲတွင် တိုက်ရိုက်
တွက်ချက်နိုင်ပြီဖြစ်သည်။ ရလဒ်သည် interpreter နှင့် stdout၊ stderr နှင့်
exit status အတိအကျ တူညီပြီး၊ မထောက်ပံ့နိုင်သေးသည့် ပုံစံများကို
`E177`/`E110`/`E111` ဖြင့် အတိအလင်း ငြင်းဆိုဆဲ ဖြစ်ပါသည်။

---

## ၁။ `sqrt` ကို native executable တွင် သုံးနိုင်ပြီ

- `sqrt(x)` ကို `akk build` တွင် ယခု သုံးနိုင်ပါပြီ။ ရလဒ်သည် အမြဲ
  **float** ဖြစ်သည် — `sqrt(16)` သည် `4.0` ဖြစ်ပြီး `4` မဟုတ်ပါ။
  integer argument ကို အရင် double အဖြစ် ပြောင်းသည်၊ interpreter က
  `as_f64` ဖြင့် လုပ်သည့်အတိုင်း ဖြစ်သည်။
- တွက်ချက်မှုကို `sqrtsd` ညွှန်ကြားချက် တစ်ခုတည်းဖြင့် လုပ်သဖြင့်
  result သည် bit အတိအကျ interpreter နှင့် တူသည်။ `-0.0` သည် မိမိ
  အမှတ်အသားအတိုင်း ကျန်ပြီး (`-0.0` ဟု print ဖြစ်သည်)၊ NaN သည်
  NaN အဖြစ်သာ ကျန်သည် — အနုတ်အဖြစ် မှားယွင်း သတ်မှတ်မခံရပါ။
- `sqrt(x)` ကို binding၊ function parameter နှင့် collection ဒြပ်စင်မှ
  တဆင့် ခေါ်လျှင်လည်း အလုပ်လုပ်သည်။ `sqrt(sqrt(16.0))` ကဲ့သို့
  အထပ်ထပ် ခေါ်ခြင်းလည်း ရသည်။

## ၂။ အနုတ်ကိန်း — interpreter ၏ `E111` အတိအကျ

- `sqrt(-4)` သည် interpreter ၏ `E111` ဖြစ်သည်၊ ထို စာကြောင်းထဲတွင်
  မှားနေသော တန်ဖိုးကို ကိုယ်တိုင် ထည့်ရေးထားသည်။ native runtime က
  ထို တန်ဖိုးကို `print` သုံးသည့် writer အတူတူဖြင့် ရေးသည် —
  integer အတွက် `rt_write_int_err`၊ float အတွက် `rt_str_float`
  (print ၏ formatter) — ထို့နောက် exit 1 ဖြစ်သည်။
- ဂဏန်း စာလုံးများ print နှင့် တစ်ထပ်တည်း ဖြစ်သဖြင့် `-4`၊ `-1.5`၊
  `-9` စသည်ဖြင့် အတိအကျ ထွက်သည်။ compiled call တွင် span မပါသဖြင့်
  `လိုင်း N တွင်` အပိုင်းသာ မပါပါ (ယခင် `E110`/`E049` များအတိုင်း)။
- ထို အမှားသည် value တစ်ခု ပြန်မပေးသဖြင့် compiled program သည်
  interpreter ငြင်းဆိုသည့် တန်ဖိုးကို ဆက်မသုံးမိပါ။

## ၃။ အခြား ငြင်းဆိုမှုများ — မပြောင်းလဲ

- argument အရေအတွက် မှား (`sqrt()`) သို့မဟုတ် ကိန်း မဟုတ်သော
  argument (`sqrt("a")`) သည် interpreter ၏ `E110` ဖြစ်ပြီး
  executable မထုတ်မီ ငြင်းဆိုသည်။
- `find`/`upper`/`lower`/`trim` ကဲ့သို့သော ကျန် builtin များ၊ library
  import၊ class၊ closure၊ destructuring၊ `null`၊ `input()` စသည်တို့ကို
  ယခင်အတိုင်း `E177` ဖြင့် ဆက်လက် ငြင်းဆဲ ဖြစ်သည်။
- run-time string ၏ `len`/index/iteration/slice/reverse သည် Unicode
  syllable table လိုအပ်သဖြင့် ဆက်လက် ငြင်းဆဲ ဖြစ်သည်။

## ၄။ တည်ငြိမ်မှုနှင့် parity

- Parity harness — match **၁၅**၊ refuse **၄၁**။ `tests/fixtures/eng_builtin.akk`
  တွင် `sqrt` ကို ယခု compile လုပ်နိုင်သဖြင့် ထို fixture ၏ ပထမဆုံး
  ငြင်းဆိုမှုသည် နောက်လာသည့် `find` ခေါ်ဆိုမှု ဖြစ်လာသည်။
  `tests/parity/expectations.txt` ကို ထိုအတိုင်း ချိန်ထားသည်။
- `E177` ၏ အကျဉ်းချုပ် စာသားတွင် `sqrt` ကို `abs`/`min`/`max` နှင့်
  အစုတစ်ခုတည်း ထည့်ထားသည်။ `docs/COLLECTIONS.md` ထဲက pinned
  စာကြောင်းကိုပါ တစ်ခါတည်း update လုပ်ထားသည်။

## ၅။ စမ်းသပ်မှု

- `cargo fmt --all -- --check` — clean (exit 0)။
- `cargo test --all-targets` — unit test ၃၁၈၊ `tests/bundle.rs` ၄၂၊
  `tests/cli.rs` ၈၊ `tests/cli_project.rs` ၁၃၊ `tests/docs_collections.rs` ၂၊
  `tests/native/` ၁၅၊ `tests/parity/` ၃ — စုစုပေါင်း **၄၀၁** အားလုံး
  အောင်မြင်၊ ကျရှုံးမှု မရှိ။
- စမ်းသပ်မှု အသစ်များ —
  `tests/native/fixtures/sqrt.akk` (integer/float argument၊ `sqrt(0)`၊
  `sqrt(-0.0)`၊ အထပ် နှစ်ဆင့်၊ binding၊ ကိန်းရှင် int/float နှစ်မျိုးဖြင့်
  parameter၊ collection ဒြပ်စင် — `--opt`/`--no-opt` နှစ်မျိုးလုံး)၊
  `a_negative_square_root_panics_like_the_interpreter` (`E111` ၏ စာသားအတိအကျ
  ကို int၊ float နှင့် parameter သုံးမျိုးဖြင့်)၊
  `sqrt_arity`/`sqrt_of_string` (`E110`)။
- `tests/native/fixtures/` တွင် stray `.exe` သို့မဟုတ် `build/`
  directory မကျန်ပါ။ Native fixture ၄၈ ခု။

## ၆။ သိထားရန် ကန့်သတ်ချက်များ

- GC/collector မရှိသေးသဖြင့် arena သည် ပုံသေ ၂၅၆ KiB ဖြစ်သည်။
- `upper`/`lower`/`trim` နှင့် `find`/`index_of` တို့သည် ဤ slice တွင်
  မပါသေးပါ — ၎င်းတို့သည် Unicode case/whitespace သို့မဟုတ်
  grapheme cluster တို့ကို မှီခိုသဖြင့် သီးခြား slice လိုအပ်သည်။
- dynamic တန်ဖိုးအပေါ် `str`/တွက်ချက်မှု dispatch လုပ်နိုင်ရန်
  တစ်လုံးတည်း NaN-boxed value သည် နောက် slice ဖြစ်သည်။
- Linux ELF output ကို ဤ host တွင် မ run နိုင်သေးပါ။ Windows `.exe`
  ကိုသာ တကယ် run စမ်းထားသည်။
- aarch64၊ Mach-O၊ register allocation၊ inlining နှင့် benchmarks
  မပါသေးပါ။
