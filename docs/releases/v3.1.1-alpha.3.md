# Akkhara `v3.1.1-alpha.3` — ထွက်ရှိမှု မှတ်တမ်း

**ထွက်ရှိသည့် ရက်စွဲ:** ၂၀၂၆ နိုဝင်ဘာ ၂၄
**အထူးအဆင့် (tag):** `v3.1.1-alpha.3`

ဤဗားရှင်းသည် `v3.1.0-alpha.3` နောက်ပိုင်း native `akk build` backend ၏
slice ကို အပိုင်းသုံးပိုင်းဖြင့် တိုးချဲ့ပါသည် — အမျိုးအစား မတူသော
collection များ၊ run-time member/key ပါသော set/dict literal ၏
allocation လျှော့ချမှု၊ နှင့် အဘိဓာန်၏ `values()`/`entries()`။
အားလုံးသည် interpreter နှင့် stdout၊ stderr နှင့် exit status
အတိအကျ တူညီပြီး၊ မထောက်ပံ့နိုင်သေးသည့် ပုံစံများကို `E177` ဖြင့်
အတိအလင်း ငြင်းဆိုဆဲ ဖြစ်ပါသည်။

---

## ၁။ အမျိုးအစား မတူသော collection များ

- runtime descriptor တွင် ဒြပ်စင်တိုင်း၏ ဘေးတွင် tag ရှိပြီးသား
  ဖြစ်သဖြင့် `[1, "two", 3.5, True]` ကဲ့သို့ အမျိုးအစား မတူသော
  list၊ tuple သို့မဟုတ် set ကို ယခု native executable ထဲ compile
  လုပ်နိုင်ပါပြီ။ print၊ `len`၊ equality၊ မိတ္တူကူးခြင်း၊ element store
  နှင့် `push`/`insert` အားလုံး ဒြပ်စင်တိုင်း၏ ကိုယ်ပိုင် tag ကို
  ဖတ်သဖြင့် interpreter နှင့် byte-by-byte တူညီပါသည်။
- analyzer ၏ element shape တွင် `Dynamic` ကို ထည့်ပါသည်။ ၎င်းသည်
  **ဒြပ်စင် shape အတွင်းသာ** သုံးသည် — တန်ဖိုးတစ်ခု၏ kind မဟုတ်ပါ။
- မတူသော အမျိုးအစား တန်ဖိုးကို ရေးသွင်းလျှင် (index store၊
  `push`/`insert`) collection ၏ element shape သည် `Dynamic` သို့
  ကျယ်သွားသည် — ငြင်းဆိုမှု မရှိတော့ပါ။ nested shape လည်း အလားတူ
  ကျယ်သည် (`[[1], [2]]` ထဲသို့ `["nine"]` ထည့်လျှင်
  `[["nine"], [2]]`)။
- `Dynamic` ဒြပ်စင်တစ်ခုကို ဖတ်ခြင်းသည် ၎င်း၏ tag ကို ပါသယ်ပြီး
  print လုပ်နိုင်သည် (အပေါ် ပုဒ် ၄)။ ထို collection ကို iteration လုပ်ခြင်း
  နှင့် `pop`/`remove`/`sort`/`sum` ကဲ့သို့ ဒြပ်စင်တစ်ခုကို အဖြေပေးသည့်
  builtin များတွင်မူ static kind မရှိသဖြင့် `E177` ဖြင့် အတိအလင်း
  ငြင်းဆဲ ဖြစ်သည် — တိတ်ဆိတ်စွာ မှားယွင်း ကုဒ် မထုတ်ပါ။
- `tests/native/fixtures/dynamic_collections.akk` — mixed literal ၏
  print/`len`/equality၊ store နှင့် `push` ဖြင့် ကျယ်ခြင်း၊ nested
  ကျယ်ခြင်း၊ run-time set member နှင့် run-time dict key — `--opt`
  နှင့် `--no-opt` နှစ်မျိုးလုံး။ `dynamic_read`၊ `dynamic_iteration`
  နှင့် `dynamic_pop` တို့က ငြင်းဆိုမှုကို pin လုပ်သည်။

## ၂။ run-time member/key ပါသော literal — တစ်ကြိမ်တည်း allocation

- `{n, 2}` ကဲ့သို့ run-time member ပါသော set နှင့် run-time key ပါသော
  dict ကို အရင် အရွယ်ချိန်ပြီး **တစ်ကြိမ်တည်း** allocate လုပ်သည်။
- `rt_fill_set`/`rt_fill_dict` က ထို descriptor ကို နေရာတွင်တင်
  ဖြည့်သဖြင့် interpreter ၏ ထည့်သည့်အစဉ်အတိုင်း duplicate ဖယ်ရှားမှု၊
  key ၏ ပထမ နေရာနှင့် နောက်ဆုံး တန်ဖိုးတို့ကို မပြောင်းဘဲ ရသည်။
- ယခင်က member တစ်ခုချင်းစီ append တိုင်း descriptor အသစ် တစ်ခုနှင့်
  ကွင်းလုံး မိတ္တူ ကူးခဲ့သဖြင့် ကွင်းထဲတွင် ထပ်ခါထပ်ခါ ပြန်တည်ဆောက်သော
  literal ငယ်တစ်ခုပင် ၂၅၆ KiB arena ကို ကုန်စေနိုင်ခဲ့သည်။
  ယခု literal တစ်ကြိမ် တည်ဆောက်တိုင်း allocation တစ်ခုသာ ဖြစ်သည်။
- `tests/native/main.rs` ၏
  `a_runtime_member_literal_allocates_once_per_evaluation` — run-time
  member ပါသော set ကို ၃၅၀၀ ကြိမ်၊ run-time key ပါသော dict ကို
  ၂၀၀၀ ကြိမ် ကွင်းထဲတွင် တည်ဆောက်ပြီး `--opt`/`--no-opt` နှစ်မျိုးလုံးတွင်
  arena မကုန်ဘဲ interpreter output အတိုင်း ပြီးဆုံးကြောင်း စစ်သည်။
  ယခင် per-member allocation ပြန်ဖြစ်လျှင် ဤ test ကျမည်။

## ၃။ အဘိဓာန်၏ `values()` နှင့် `entries()`

- `keys(d)` ဘေးတွင် `values(d)` နှင့် `entries(d)` ကို ယခု native
  executable ထဲ compile လုပ်နိုင်ပါပြီ။ ဒြပ်စင် descriptor တွင်
  value တိုင်း၏ ကိုယ်ပိုင် tag ပါပြီးသားဖြစ်သဖြင့် `values` က value
  word တိုင်းကို ၎င်း၏ tag နှင့်အတူ ကူးယူပြီး `entries` က အတွဲတိုင်းအတွက်
  `(key, value)` tuple တစ်ခု ဆောက်သည် — နှစ်မျိုးလုံး ထည့်သည့်အစဉ်အတိုင်း
  list တစ်ခု ပြန်ပေးသည်။
- ရလဒ်သည် သာမန် list ဖြစ်သဖြင့် print၊ `len`၊ index၊ `for` နှင့်
  equality အားလုံး အလုပ်လုပ်သည်။ စာသား value များသာ ပါသော dict တွင်
  entry ၏ နေရာကို ဖတ်နိုင်သည်၊ list value များ ပါသော dict တွင် nested
  shape အတိုင်း ဆက်ဖတ်နိုင်သည်၊ အမျိုးအစား မတူသော အဖိုးများ ပါလျှင်
  tuple သည် `Dynamic` အဖြစ် ကျယ်ပြီး ထို entry အတွင်းမှ ဖတ်ခြင်းကို
  `E177` ဖြင့် ငြင်းသည်။
- dict မဟုတ်သော argument နှင့် argument အရေအတွက် မှားလျှင် interpreter ၏
  `E110` ကို လိုင်းနံပါတ်မပါဘဲ ထုတ်သည်။
- `tests/native/fixtures/dict_views.akk` — `values`/`entries`/`keys`
  print/`len`/index/iteration၊ စာသား value dict တွင် entry နေရာဖတ်ခြင်း
  နှင့် list value dict ၏ nested shape — `--opt`/`--no-opt` နှစ်မျိုးလုံး။
  `values_of_list` နှင့် `entries_arity` တို့က `E110` ငြင်းဆိုမှုကို pin
  လုပ်သည်။

## ၄။ dynamic ဒြပ်စင် ဖတ်ခြင်း

- အမျိုးအစား မတူသော collection မှ ဒြပ်စင်တစ်ခုကို ယခု ဖတ်နိုင်ပါပြီ။
  descriptor က ဒြပ်စင်တိုင်းကို `{ tag, word }` အတွဲအဖြစ် သိမ်းထားသဖြင့်
  ဖတ်လိုက်သည့် တန်ဖိုးသည် ထို **အတွဲ၏ လိပ်စာ** ကို သယ်သည် — tag နှင့်
  word ကို ကူးယူစရာ မလိုဘဲ တစ်ကြိမ်တည်း ရသည်။
- `rt_index_seq_ref`/`rt_index_dict_ref` က ပုံမှန် ဖတ်ခြင်း၏ index/key
  စစ်ဆေးမှု (လိုင်းနံပါတ်ပါ `E049`/`E053`) အတိုင်း အတွဲလိပ်စာကို
  ပြန်ပေးပြီး၊ ယခင် `rt_index_seq`/`rt_index_dict` က ၎င်းမှ word ကို
  ဖတ်သော ပါးလွှာသည့် wrapper ဖြစ်လာသည်။ collection ကို ရေးတိုင်း
  descriptor အသစ် ကူးသဖြင့် ဤလိပ်စာသည် မပြောင်းလဲဘဲ တည်ရှိသည်။
- Print လုပ်လျှင် သိမ်းထားသည့် tag အလိုက် ခွဲခြမ်းသည် —
  `rt_print_dynamic` က int/float/bool/string ကို ပုံမှန် print လမ်းအတိုင်း
  (string ကို quote မပါဘဲ) ရေးပြီး၊ collection ဖြစ်လျှင်
  `rt_print_collection` ၏ `repr` ကို ရေးသည်။ ဤတန်ဖိုးကို binding ထဲ
  ထည့်ခြင်း၊ function parameter ဖြင့် သယ်ခြင်း၊ `[xs[1], xs[0]]` ကဲ့သို့
  literal အသစ်ထဲ ထည့်ခြင်း (set member နှင့် dict value အပါ)
  တို့တွင်လည်း tag ပါ လိုက်ပါသည်။
- `str`၊ တွက်ချက်မှု၊ နှိုင်းယှဉ်ချက်၊ condition၊ `len`၊ ထို collection ကို
  iteration လုပ်ခြင်းနှင့် `pop`/`remove`/`sort`/`sum` တို့သည် static kind
  တစ်မျိုးတည်း လိုအပ်သဖြင့် `E177` ဖြင့် အတိအလင်း ငြင်းဆဲ ဖြစ်သည်။
- `tests/native/fixtures/dynamic_reads.akk` — int/string/float/bool ဖတ်ခြင်း၊
  binding နှင့် literal အသစ်၊ collection တန်ဖိုး ဖတ်ခြင်း၊ parameter၊
  nested ဖတ်ခြင်း၊ mixed value dict (တိုက်ရိုက်နှင့် `values`/`entries`
  မှတစ်ဆင့်) နှင့် mixed member set — `--opt`/`--no-opt` နှစ်မျိုးလုံး။
  `dynamic_str` နှင့် `dynamic_arithmetic` တို့က ငြင်းဆိုမှုကို pin လုပ်သည်။

## ၅။ တည်ငြိမ်မှုနှင့် ငြင်းဆိုမှုများ

- Slice အပြင်ဘက် construct များကို ခန့်မှန်းမနေဘဲ `E177` ဖြင့်
  အတိအလင်း ငြင်းဆိုဆဲ ဖြစ်ပြီး၊ ငြင်းခံရသော ပရိုဂရမ်တစ်ခုမှ
  executable မထုတ်ပါ။
- `Dynamic` တန်ဖိုးအပေါ် `str`/တွက်ချက်မှု/နှိုင်းယှဉ်ချက်၊ run-time string ၏ `len`/index/iteration၊
  `slice`/`join`/`contains` စသည့် ကျန် collection builtin များ၊
  library import၊ class၊ closure နှင့် function value၊ destructuring၊
  run-time default parameter၊ `null`၊ `input()` တို့ကို ဆက်လက်
  ငြင်းဆဲ ဖြစ်သည်။
- Parity harness — match **၁၅**၊ refuse **၄၂**။ ဤဗားရှင်းတွင်
  `tests/parity/expectations.txt` မပြောင်းပါ။
- `docs/COLLECTIONS.md` တွင် mixed-kind ဒြပ်စင် ရောထည့်ခြင်းကို
  ယခင် မထောက်ပံ့သေးဟု ကျန်ခဲ့သော စာသားကို ယခု ထောက်ပံ့ပြီး
  (ဖတ်ခြင်းသာ ငြင်းသည်) ဖြစ်အောင် ပြင်ထားသည်။

## ၇။ သိထားရန် ကန့်သတ်ချက်များ

- GC/collector မရှိသေးသဖြင့် arena သည် ပုံသေ ၂၅၆ KiB ဖြစ်သည်။

  သယ်ဆောင်ခြင်းတို့ ရပြီဖြစ်သည်။ tag အလိုက် `str`/တွက်ချက်မှု
  dispatch လုပ်နိုင်ရန် တစ်လုံးတည်း NaN-boxed value သည် နောက်
  slice ဖြစ်သည်။
- Linux ELF output ကို ဤ host တွင် မ run နိုင်သေးပါ။ Windows `.exe`
  ကိုသာ တကယ် run စမ်းထားသည်။
